# Deploy the RWE ADS Automation bundle

Serverless DAB. Deploys jobs + a DLT pipeline + a Databricks App. **Point it at YOUR own catalog** — the repo baseline (`rwe_ads_catalog`, host, warehouse id) is a placeholder you must change.

## 1. One-time prereqs (before `bundle deploy`)

**First, create your local config:** copy `demo.config.example.yaml` -> `demo.config.yaml` and fill in your workspace/warehouse/catalog. `demo.config.yaml` is gitignored, so your real values never get committed. (`lib/config.py` reads `demo.config.yaml` at runtime; a local copy must be present for `bundle validate`.)

> **Guard:** `app/demo.config.yaml` is a build artifact regenerated by `build.py` from the root config; keep the committed copy as placeholders — never commit real values into it.

1. **A Unity Catalog you own.** The bundle NEVER runs `CREATE CATALOG`. Set `catalog:` in `demo.config.yaml` to your catalog. The `ads_*` schemas + volume are created by wave0 (`CREATE SCHEMA IF NOT EXISTS`) — you need `CREATE SCHEMA` on the catalog.
2. **A Lakebase Autoscaling project** — the App binds it at deploy time, so create it FIRST:
   ```
   databricks postgres create-project rwe-ads-lakebase --profile <p>
   ```
   Match `lakebase.project:` in `demo.config.yaml`. (The retired Provisioned tier / `w.database` is NOT used; the serverless waves make ZERO in-kernel `w.postgres` calls.)
3. Set `warehouse_id:` (a **serverless** SQL warehouse) and the target `host:` to your workspace.

## 2. Deploy + run

**Deploy-time `--var` flags (do not skip).** Five bundle vars are resolved at `bundle deploy` time and CANNOT read `demo.config.yaml`; passing them wrong/missing is the #1 setup failure (pipeline + app come up on the placeholder `rwe_ads_catalog` and error). Set once, matching your `demo.config.yaml`, and append to EVERY deploy/run:
```
VARS="--var uc_catalog=<catalog> --var silver_schema=<schemas.curated> --var warehouse_id=<workspace.warehouse_id> --var lakebase_project=<lakebase.project> --var notification_email=<your-email>"
```
```
databricks bundle validate -t dev --profile <p>     # expect exit 0 (1 benign sync.exclude warning: __pycache__)
databricks bundle deploy   -t dev --profile <p> $VARS

databricks bundle run wave0_foundation       -t dev --profile <p> $VARS   # 5 ads_* schemas, protocols volume, approved-SQL KB, VS index (no-op unless VS on)
databricks bundle run wave1_synth_bronze      -t dev --profile <p> $VARS   # synth RWD + protocol extract (auto-seeds sample docs if the volume is empty) + medallion silver/gold
databricks bundle run wave3_ads_build         -t dev --profile <p> $VARS   # protocol eval (validate->flag) + approve gate + ADS build (EXPLAIN-gated)
databricks bundle run wave5_serving_audit     -t dev --profile <p> $VARS   # audit tables + serving no-ops
databricks bundle run wave4_model_benchmark  -t dev --profile <p> $VARS   # OPTIONAL model benchmark + cost (real LLM calls)
databricks bundle run rwds_ads_studio         -t dev --profile <p> $VARS   # app resource key -> deploys the app (name from resources/app.yml, e.g. <initials>-rwe-ads-app)
bash scripts/setup_synced_tables.sh                                  # Delta -> Lakebase synced tables (control-plane create-synced-table)
```
(Job key `wave4_model_benchmark`; label "Model benchmark + cost" — model benchmarking + cost only, no Agent Bricks Supervisor.)

## 3. Verify (measured, not log-only)
- Extraction: `SELECT study_id, review_status FROM <catalog>.ads_raw.protocol_spec` (3 sample rows).
- ADS output: `SELECT count(*) FROM <catalog>.ads_serving.ads_output`.
- Serving in Postgres: query `public.ads_output` on the Lakebase endpoint.
- MLflow tracing: `python3 scripts/verify_tracing.py --profile <p>` (**exits non-zero if zero traces** — a gate that can't run must FAIL, never silently pass) OR `GET /api/2.0/mlflow/traces?experiment_ids=<id>`.

## Gotchas (full list in CLAUDE.md)

- **Vector Search is optional + off by default.** KB retrieval keyword-matches by default; to activate real VS, set `vector_search.enabled: true` and create (or point `approved_sql_kb.vs_endpoint` at) an `ads-vs-endpoint` endpoint. `waves/wave0_foundation/build_index.py` (the `build_kb_index` task, in **Wave 0** — foundation infra) then builds a TRIGGERED delta-sync index (`databricks-gte-large-en` over `description`, pk `snippet_id`); while disabled it is a clean no-op (`status: disabled`). Creating an endpoint is a billable operator step, so it is never auto-provisioned.
- **Frontend build is networked, but committed — so deploy needs no build.** The app's `app/static` bundle is prebuilt AND committed to the repo, so a clean clone deploys as-is. You only need to rebuild when you changed the frontend under `app/frontend/`: run `python app/build.py` (the one command — it runs `npm ci && npm run build`, falling back to `npm install` with no lockfile) on a machine with public-npm access. If `app/static` is already current, skip it. The `bundle deploy` does NOT build the frontend.
- Modern reasoning models (Claude 5 / GPT-5 / Gemini 3.x) reject `temperature != 1` — `gateway_call` omits it.
- MLflow tracing uses a per-user experiment (`/Users/<you>/<initiative>`) so it persists on serverless jobs.
- `ai_extract` v2.1 + `mode=precision` returns each scalar as `{value, citation_ids, confidence_score}` — read `:value`.
- 1 benign `sync.exclude` validate warning (`**/__pycache__/**` "does not match any files") — it only matches after Python has run locally; ignore it and don't delete the excludes. (The `app/frontend/**` exclude keeps the build-time frontend source out of the deployed app payload; the app serves the committed `app/static` bundle.)
