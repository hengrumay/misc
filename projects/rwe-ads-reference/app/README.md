# RWE ADS Automation App

## Overview

A Databricks App (React 19 + FastAPI) for the RWE Analysis-Ready Dataset (ADS) Automation PoC.

**Architecture:**
- **Frontend:** React 19 + Vite + TypeScript + TailwindCSS v4 (HSL design tokens) + Framer Motion
- **Backend:** FastAPI + Uvicorn, Lakebase connection manager (SQLAlchemy + psycopg + OAuth token refresh)
- **Deployment:** Databricks Apps monolith; binds `$DATABRICKS_APP_PORT`
- **Data:** Reads ADS serving data from Lakebase (low-latency Postgres); writes app state to Lakebase app-state DB

## Key Design Decisions

### Backend

1. **Config-Agnostic:** All catalog/schema names resolved via `lib/config.py` (reads `demo.config.yaml`).
   - No hardcoded names in code.
   - Local dev: falls back to CLI profile via `LAKEBASE_PROFILE` env var.
   - Deployed: `DATABRICKS_CLIENT_ID`/`_SECRET` injected by Databricks Apps.

2. **3-Tier Data Fallback:** All read endpoints return `{"source": "lakebase"|"warehouse"|"synthetic", ...}` to ensure UI never crashes.
   - Reads from Lakebase first (low-latency Postgres).
   - Falls back to warehouse SQL.
   - Falls back to synthetic labeled data.

3. **Monolith Pattern:** Single FastAPI app serves:
   - `/api/*` endpoints (REST API for the frontend).
   - `/assets` static mount (built Vite bundle).
   - `/{path}` SPA catch-all (client-side routing).

4. **Lakebase Connection Manager:**
   - Async SQLAlchemy + psycopg with OAuth token refresh.
   - Token TTL = 60 min; `pool_recycle=1800s` (recycle before expiry).
   - Deployed: WorkspaceClient() auto-auth.
   - Local: falls back to CLI profile.

### Frontend

1. **Theme System:** HSL design tokens with light/dark support.
   - Databricks branding (lava red #FF3621, navy #1B3139).
   - Progressive type scaling at 1280/1600/1920/2560px breakpoints.
   - Theme persisted to localStorage.

2. **Accessibility:**
   - Native semantics (`<button>`, `<select>`).
   - Focus rings (`--ring` token).
   - Muted text kept ≥70% lightness for WCAG contrast.

3. **Pages (Sidebar Order):**
   1. **How It Works** (FIRST) — FlowDiagram animated dots flow: 7 steps + guardrails lanes.
   2. **Protocols** — Upload + view parsed specs.
   3. **Build ADS** — Trigger build, watch steps, inspect SQL per step (copy buttons).
   4. **Review & Sign-off** — Analyst review queue + e-signature modal.
   5. **Served ADS** — Browse ads_output + cohort_summary from Lakebase (Recharts charts + table).
   6. **Audit & Reproducibility** — Reproducibility manifests + version hashes + reviewer info.

4. **Components:**
   - **Navbar:** Fixed top, theme toggle, logo.
   - **Sidebar:** Collapsible (persist to localStorage), persisted collapse state, mobile drawer overlay.
   - **SourcePill:** Shows data source (lakebase/warehouse/synthetic) with pulsing dot.
   - **ErrorBoundary:** Catch unhandled errors, show friendly message + reload button.
   - **FlowDiagram:** Reused from `how-it-works-flow` skill; glass nodes + animated bezier paths + riding dots.

5. **Page Transitions:** Framer Motion fade-in-up with staggered children.

6. **Lazy Routes:** All pages lazy-loaded with `React.lazy` + `Suspense` for small first-paint bundle.

## Development (Local)

### Prerequisites
- Node.js 18+
- Python 3.9+
- Databricks CLI configured (or `LAKEBASE_PROFILE` set)

### Frontend Dev
```bash
cd app/frontend
npm install
npm run dev
```
Vite dev server at http://localhost:5173 with proxy to http://localhost:8080/api.

### Backend Dev
```bash
cd app/backend
python -m venv venv
source venv/bin/activate  # or `venv\Scripts\activate` on Windows
pip install -r ../requirements.txt
LAKEBASE_PROFILE=DEFAULT python -m uvicorn app:app --host 0.0.0.0 --port 8080
```
Backend at http://localhost:8080/api.

### Full Build
```bash
# From app/ root — the one command:
python build.py
```
- Runs `npm ci && npm run build` in `frontend/` (falls back to `npm install` if there is no lockfile).
- Outputs the built bundle to `app/static/`.
- Ready for `databricks bundle deploy`.

> **The built `app/static/` bundle is committed to the repo.** A clean clone deploys
> as-is — you only need to re-run `python build.py` (a networked step: it fetches npm
> packages) when you've changed the frontend under `app/frontend/`. If `app/static/` is
> already current, skip the build.

## Deployment (Databricks Apps)

### 1. Build
```bash
cd app
python build.py
```

### 2. Sync to Workspace
```bash
databricks workspace export app --debug --output app --format DIRECTORY
```
Or use `databricks bundle sync` if in a bundle.

### 3. Deploy App

> **Recommended: deploy via the bundle**, not the raw `apps` CLI. `databricks bundle deploy`
> creates the app **and binds its resources** (SQL warehouse, Lakebase, the app-triggered jobs);
> `databricks bundle run rwds_ads_studio` then deploys the code and starts it. A code-only
> `databricks apps deploy` leaves the app's resource bindings null (dead buttons). See the
> repo `README.md` / `docs/RUNBOOK.md` for the `bundle deploy … $VARS` + `bundle run rwds_ads_studio … $VARS` flow.

The raw `apps` CLI (below) is a fallback — substitute your own unique app name for
`<initials>-rwe-ads-app` (apps are NOT dev-prefixed, so the name must be unique on the workspace):

```bash
databricks apps create --source-code-path ./app --name <initials>-rwe-ads-app
```

Or update:
```bash
databricks apps update <initials>-rwe-ads-app --source-code-path ./app
```

### 4. Start App
```bash
databricks apps start <initials>-rwe-ads-app
```

The app:
- Builds with `python app/backend/app.py` (runs FastAPI).
- Binds to `$DATABRICKS_APP_PORT` (injected by runtime, typically 8080).
- Serves built frontend from `static/`.
- Auto-authenticates via injected `DATABRICKS_CLIENT_ID`/`_SECRET`.

## 3-Tier Data Fallback Pattern

**Problem:** Reads can fail if Lakebase is down or slow.  
**Solution:** Fallback chain with labeled source indicator.

```python
@app.get("/api/served/ads_output")
async def get_ads_output(limit: int = 100):
    # Try 1: Lakebase (low-latency)
    try:
        rows = await lakebase.execute_read(
            f"SELECT * FROM {cfg().lakebase_serving_db}.ads_output LIMIT {limit}"
        )
        return {"source": "lakebase", "rows": rows, ...}
    except Exception:
        pass
    
    # Try 2: Warehouse SQL
    try:
        rows = warehouse.execute(f"SELECT * FROM {cfg().table('serving', 'ads_output')} LIMIT {limit}")
        return {"source": "warehouse", "rows": rows, ...}
    except Exception:
        pass
    
    # Try 3: Synthetic (labeled as degraded)
    return {"source": "synthetic", "rows": [synthetic_sample_rows()], ...}
```

Frontend's `SourcePill` shows:
- Green "Lakebase" when live.
- Amber "Warehouse" as fallback.
- Amber "Synthetic" as degraded mode (with badge).

## Environment Variables

### On Databricks Apps (injected)
- `DATABRICKS_CLIENT_ID` — Service principal client ID.
- `DATABRICKS_CLIENT_SECRET` — Service principal client secret.
- `DATABRICKS_APP_PORT` — Port to bind (set by runtime).

### Local Dev (set manually)
- `LAKEBASE_PROFILE` — CLI profile name (default: `DEFAULT`).
- `ADS_CONFIG_PATH` — Path to `demo.config.yaml` (auto-discovered if not set).

### Optional Overrides (via app.yaml `env:`)
- `ADS_CATALOG` — Override catalog in demo.config.yaml.
- `ADS_LAKEBASE__INSTANCE` — Override Lakebase instance.

## Lakebase Connection Details

**Serving DB (read-only):**
- Instance: `cfg().lakebase_instance` (e.g., `<your-lakebase-project>`)
- Database: `cfg().lakebase_serving_db` (e.g., `ads_serving_pg`)
- Tables: `ads_output`, `cohort_summary` (synced from Delta)

**App State DB (read/write):**
- Instance: `cfg().lakebase_instance`
- Database: `cfg().lakebase_app_db` (e.g., `ads_app`)
- Tables: `sessions`, `review_queue`, `sign_offs` (app-specific)

## Reproducibility & Audit

Every ADS build emits a manifest (`/api/audit/reproducibility`) with:
- Protocol version
- KB snippet versions + SHA256 hashes
- Generated SQL + hash
- Source Delta table versions @ time of build (time travel)
- Model ID
- Eval scores (coherence, consistency)
- Reviewer name + e-signature timestamp
- Deterministic re-run: exact same inputs → exact same outputs

## PHI-Containment

- All model/agent calls → Unity AI Gateway with PHI-aware masking.
- Contextual Service Policy denies external egress.
- Data is synthetic (PHI-safe by construction).
- Controls transfer to your production workspace with real RWD.

## Validation-Not-Execution

- ADS builder assembles SQL from approved KB templates (deterministic — no model generates it).
- Backend validates syntax + EXPLAIN.
- Backend executes against synthetic gold only.
- No access to real patient DB possible by construction.

## Notes

- **Synthetic data:** All data is generated deterministically (seed: 20260812) for reproducibility.
- **E-Signature:** Simple text signature (typed name) + timestamp. In production, integrate PKI + timestamping authority.
- **Serverless compute:** All jobs, SDP, Model Serving, SQL Warehouse are serverless.
- **No hardcoded names:** Every catalog/schema/table/endpoint name flows through `lib/config.py`.
